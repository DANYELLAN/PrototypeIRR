Action: Microsoft Teams / Post adaptive card and wait for a response
   Post as: Flow bot
   Post in: Group chat
   Group chat (custom value): 19:8fa29ff440e743f495bbd994832463ff@thread.v2
   Adaptive Card: paste assistance-card.json from this folder
   Update message: This assistance request has been resolved.

Rename the action Post_adaptive_card_and_wait_for_a_response if needed to
match the expressions below, or substitute its actual action name.

Action after a successful response: SharePoint / Update item
   Site and list: same as the trigger
   ID: triggerBody()?['ID']
   Title: triggerBody()?['Title']
   RequesterName: triggerBody()?['RequesterName']
   MachineNumber: triggerBody()?['MachineNumber']
   WONumber: triggerBody()?['WONumber']
   AssistanceNeeded: triggerBody()?['AssistanceNeeded']
   RequestStatus: Resolved
   ResolvedBy: body('Post_adaptive_card_and_wait_for_a_response')?['responder']?['displayName']
   ResolutionNote: body('Post_adaptive_card_and_wait_for_a_response')?['data']?['resolutionNote']
   ResolvedAt: utcNow()

Use the Expression tab for the expressions above. The adaptive card action
waits for one response from any member. The first response completes that
run. Configure failure alerts for the flow so a failed SharePoint update can
be corrected even if the original Teams card has already been acknowledged.

4. On Server 2, set these root .env values and restart the time-entry app:
   CNC_TIME_NOTIFICATION_TRANSPORT=sharepoint
   CNC_TIME_ASSISTANCE_SHAREPOINT_LIST_ID=5212c19a-705e-4fb5-aefc-8a30c7da77b6
   CNC_TIME_SHAREPOINT_TOKEN_CACHE_FILE=.msal_token_cache.json

No public callback URL is required. The app reads RequestStatus, ResolvedBy,
ResolutionNote, and ResolvedAt from SharePoint while the operator watches
the request. It displays Resolved with the responder and resolution time.

   Verify one card appears in the shared chat, one responder can resolve it,

webhook / local outbox route. Locally queued requests are not replayed
